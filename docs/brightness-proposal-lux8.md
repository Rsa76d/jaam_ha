# Плавна яскравість від датчика освітлення, яскравість дисплея, режим лампи

База: **5.1.2-b3**. Робоча версія: `5.1.2-b3-lux8`. Збирається для ESP32 і ESP32-C3 без нових залежностей. Ліцензія змін та сама, що й проєкту (CC BY-NC-SA 4.0).

## Навіщо

У 4.x яскравість мапи плавно залежала від датчика освітлення. У 5.x лишився тільки ступінчастий вибір «день/ніч» за порогом, а дисплей має лише увімкнення й вимкнення вночі. Пропоную повернути плавну яскравість, додати регулювання яскравості дисплея й керувати цим із Home Assistant.

## Що додано (для користувача)

**Режими яскравості мапи** (існуючий вибір доповнено четвертим пунктом):

| № | Режим | Поведінка |
|---|---|---|
| 0 | Вимкнено | Постійна «Основна яскравість», як було |
| 1 | День/Ніч | «День» або «Ніч» за годинником, як було |
| 2 | Сенсор освітлення | Ступінчастий. Світло вище порога дає «Велика», нижче дає «Мала». Яка саме «Мала» (день чи ніч), вирішує годинник |
| 3 | Автояскравість | **Новий.** Плавно між «Малою» і «Великою» залежно від освітлення |

Повзунки режимів 2 і 3: «Велика яскравість», «Мала яскравість день», «Мала яскравість ніч». Окремо для режиму 3: «Чутливість сенсора» (0,1–30×). Для режиму 2 лишається існуючий поріг освітлення. Порядок «Мала ніч ≤ Мала день ≤ Велика» зберігається завжди.

**Дисплей:** повзунок яскравості, перемикач «Автояскравість дисплея» (за ним з'являється «Мінімальна яскравість дисплея»), існуючий «Вимикати дисплей вночі».

**Лампа:** перемикач «Прив'язати яскравість лампи до загальної яскравості» (за замовчуванням увімкнений, поведінка як раніше). Вимкнений: лампа бере яскравість лише зі свого повзунка. Також режим мапи «Лампа» вмикає дисплей, який вимкнений вночі за часом, а після виходу з лампи дисплей знову гасне.

## Алгоритм

**Освітленість у частку 0…1** (`getSmoothedLightFraction`, спільна для мапи й дисплея):
1. `l = ln(1 + lux · чутливість)`.
2. Експоненційне згладжування за часом, τ ≈ 3 с. Залежить від реального інтервалу між викликами, а не від їх кількості.
3. `t = згладжене / ln(1 + 300)`. Опорне значення 300 лк при чутливості 1,0.
4. Біля країв «прилипання»: `t < 0,01` дає 0, `t > 0,99` дає 1.

**Режим 3** (`getSmoothSensorBrightness`):
- `мала = нічна, якщо зараз ніч за годинником, інакше денна`.
- `ціль = мала + (Велика − мала) · t`.
- Крок до цілі щопівсекунди: `clamp(round(|різниця| / 4), 1, 5)` відсотків. Мертва зона 1,5% (0,5% на краях, щоб точно виходити на мін/макс).
- Згори результат обмежується «Великою» одразу. Знизу не обмежується, щоб на межі дня й ночі зміна була плавною.
- Поточна яскравість (`CURRENT_BRIGHTNESS`) у цьому режимі тримається лише в RAM і не пишеться в NVS, щоб не зношувати флеш.

**Режим 2:** «ніч» настає нижче порога `NIGHT_MODE_LIGHT_THRESHOLD`, назад у «день» повертається при освітленості вище порога на 20% (мінімум на 1 лк): односторонній гістерезис, як у офіційній версії. Темно дає «Малу» за годинником, світло дає «Велику».

**Нічний режим** («Нічний» у меню/кнопці) у режимах 2 і 3 вмикає «Малу ніч».

**Дисплей:** `ціль = мін + (макс − мін) · t`, те саме згладжування й крок. Контраст `= round((p/100)² · 255)`, мінімум 1, через `U8g2::setContrast`.

**SH1106:** U8g2 ініціалізує його як SSD1306 (pre-charge `0xF1`), і панель насичується, тому контраст майже не змінює яскравість. Після старту надсилається `0xD9, 0x1F` (значення з Adafruit SH1106G), після чого регулювання охоплює весь діапазон.

**Лампа** (`JaamLed::lampBrightness`): прив'язано — `brightnessRelative(лампа%)` (множення на загальну яскравість), інакше — `brightnessMapped(лампа%)`.

## WebSocket API

- `initial_state` і `brightness_change` містять `brightness`: `mode`, `max`, `min_day`, `min_night`, `sensitivity`, `current`, `display`, `display_auto`, `display_min`, `display_off_at_night`, `display_current`, `sensor`.
- Команда `{"type":"set_brightness","key":"<ключ>","value":<значення>}` приймає ключі: `mode`, `max`, `min_day`, `min_night`, `sensitivity`, `display`, `display_auto`, `display_min`, `display_off_at_night`. Значення обмежуються діапазонами; прошивка тримає порядок «мала ніч ≤ мала день ≤ велика» і розсилає виправлене значення.
- Поточна яскравість під час плавної зміни надсилається не частіше 1 разу на секунду.

## Інтеграція `jaam_ha` (окремий репозиторій)

Сутності створюються тільки якщо прошивка повідомляє об'єкт `brightness`; зі стандартною прошивкою нічого не змінюється. Додано: `select` режиму яскравості, шість `number` (велика, мала день, мала ніч, чутливість, яскравість дисплея, мінімум дисплея), два `switch` (автояскравість дисплея, вимикати дисплей вночі), два `sensor` поточної яскравості. Переклади uk/en. Три тести `pytest` проти емульованого пристрою.

## Нюанс, який варто врахувати

Чутливість задає, при якій освітленості досягається «Велика» (1,0 дає ≈ 300 лк). При великих значеннях (наприклад 20–30×) «Мала» досягається лише при освітленості нижче сотих часток люкса, а датчик BH1750 має крок 0,5 лк і бачить власну підсвітку мапи. У користувача «Мала» перестає діяти. Пропозиція: обмежити діапазон чутливості (наприклад до 10×) або додати поріг «темряви» (нижче ≈1 лк вважати темрявою).

## Як перевірено

- Збірка `esp32` і `esp32c3` без попереджень компілятора.
- Алгоритм плавної яскравості прогнано окремо на комп'ютері зі сценаріями «світло/темрява», зміна «Великої» і «Малих».
- На залізі (SH1106G 128×64, BH1750): перші тести на ESP32-C3, подальші, зокрема остання версія, на ESP32. Перевірено режими 2 і 3, яскравість дисплея, лампу з перемикачем і нічне вимкнення дисплея. Довгих випробувань на різних платах ще не було.
- **Не перевірено на залізі:** дисплеї SSD1306 і SH1107 (код загальний, pre-charge чіпається тільки для SH1106).

## Пропозиція щодо розбиття на pull request

1. Режими яскравості мапи (2, 3), чутливість, API і веб-інтерфейс.
2. Яскравість дисплея разом з виправленням SH1106.
3. Режим лампи (перемикач прив'язки й дисплей вночі).
4. Окремо: сутності Home Assistant в `jaam_ha`.

Енергосистема й радіація домашнього регіону в WebSocket API (`home_energy`, `home_radiation`) теж є в моїй гілці, але до яскравості не стосуються і можуть піти окремим PR.
